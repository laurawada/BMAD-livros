- (constraint) Fonte de catálogo é Google Books API; sem cadastro manual de livros no MVP. Cada livro salvo localmente deve manter externalId para evitar duplicação conforme data-model.md.
- (constraint) Autenticação é e-mail/senha com senha em hash; sem OAuth. Foto é URL opcional/avatar padrão; capas vêm do provedor; sem upload de arquivo.
- (constraint) Review é editável/removível pelo autor; média do livro reflete imediatamente criação, edição ou remoção; status de leitura é um valor único por usuário-livro, persistido em Shelf.
- (constraint) MVP single-maintainer/full-stack: minimizar componentes operacionais e custo, priorizar fluxo simples e manter fora chat, mensagens privadas, seguidores, uploads, login social e cadastro manual.
- (decision) AD candidate: use a modular monolith on Next.js App Router (TypeScript) with Supabase-managed PostgreSQL/Auth; one deployable app, no separate API service or microservices. Official Next.js 16.3.6 docs show create-next-app defaults include App Router/TypeScript; Supabase documents a with-supabase starter for Next.js and cookie Auth.
- (decision) AD candidate: deploy the single Next.js application to Vercel Hobby and use Supabase Free for prototype/MVP while eligible; no paid SLA. Official pricing lists Hobby at for personal/non-commercial use; Supabase Free is but pauses projects after one week inactivity, with 500 MB database and two active projects. Revisit before commercial operation or when pause/availability limits are unacceptable.
- (decision) AD candidate: Google Books remains the search authority; do not persist every search hit or build local title/author text indexes. On first add-to-shelf or review, upsert the volume metadata by unique Google volume externalId; thereafter app-owned data resolves by local Book UUID. Search results remain in provider order.
- (decision) AD candidate: use PostgreSQL UUID primary keys; Google Books externalId as text unique; rating as NUMERIC(2,1) constrained to 1.0–5.0 in 0.5 increments; timestamps as timestamptz; Shelf status constrained to the four product values; BookVibe as extensible text with uniqueness per user/book/vibe. Review is one mutable row per user/book; edit in place, delete on user request. Derive book averages via AVG(Review.rating) on read after committed writes; do not persist a cache in MVP.
- (constraint) Google Books requires attribution adjacent to search/results, a prominent Google Books link for every result, and unaltered provider search ordering/content; include compliance in UI and do not intermix/re-rank Google results. Official terms state the API app may not charge a use fee without separate agreement or written permission; monetization is blocked pending provider/legal review.
- (constraint) Every exposed PostgreSQL table must have least-privilege grants and RLS policies; test policies. Use request-scoped Supabase SSR clients and verified claims for server-side authorization; never expose service-role secrets to browser code. Server mutations own multi-row consistency.
- (decision) User chose half-star ratings: PostgreSQL NUMERIC(2,1) with checks rating >= 1 and <= 5 and rating*2 is integral; display provider average as the arithmetic AVG of app Review rows, never Google Books' rating.
- (decision) Use Supabase Auth as identity source; app profile id is the Auth UUID and passwords are never stored in public User rows. Use request-scoped cookie SSR clients; server components read, server actions mutate, and Route Handlers proxy Google Books. Browser receives only publishable credentials; all exposed table grants/RLS are least privilege and policy-tested.
- (decision) All writes flow through server-only application commands. Use a Postgres invoker RPC/transaction for first-use Book upsert plus Shelf/Review mutation so unique externalId, unique user-book Shelf/Review and same-status state cannot diverge; enforce constraints/RLS in SQL, never trust UI checks alone.
- (direction) Current official evidence at authoring: Next.js installation docs version 16.3.6 (2026-07-21) require Node.js >=20.9; Google Books public volume search needs API key or access token, supports intitle/inauthor and pagination max 40; PostgreSQL built-in text-search indexes exist but are not selected for MVP.
- (question) Before charging users or operating commercially, re-evaluate Vercel Hobby eligibility and Google Books API Terms; Google states an app may not charge a fee without separate agreement or written permission. Choose an allowed commercial host/provider or obtain permission before enabling monetization.
- (question) At MVP scale, use unique constraints and B-tree indexes for externalId, foreign keys, owner-filtered rows and feed ordering; no title/author text index. Revisit local search/indexing only if provider quotas, latency or product requirements make Google Books search inadequate.
- (question) Operational envelope beyond prototype: Supabase Free pauses after one week inactive and lacks automatic backups per pricing; Vercel Hobby is but personal/non-commercial. Choose paid plans, backup/restore targets, and stronger availability only before real production/commercial launch.
- (decision) User approved MVP visibility: book pages, reviews, vibes, profile name/photo, and only Lido recent-read entries are public; all other Shelf rows/statuses are private to owner. RLS grants/policies implement this, with ownership-only writes.
- (decision) Use separate Supabase Free projects for development/preview and production, within the currently listed limit of two active projects; keep schema changes as versioned SQL migrations. This prevents test data/auth from mixing while adding no paid service, but the inactive dev project can pause and be restored.
- (decision) Shelf-only add creates status Quero ler; repeating add preserves existing status; shelf-entry removal is outside MVP. Review deletion preserves independent Shelf state; createdAt is immutable, updatedAt advances on edit, and review feeds sort by createdAt DESC then id DESC.
- (decision) Half-star ratings use PostgreSQL unconstrained NUMERIC NOT NULL with range and half-step database checks; API submits integer half-star units 2-10. Book and user AVG values derive from committed reviews and share two-decimal display rounding.
- (decision) Google volume id maps to unique Book.externalId; first-use adoption is atomic and idempotent. Provider fields map in one adapter; search uses zero-based pages of 20 without reordering; local text index remains deferred. Shelf.updatedAt tracks status changes; public Lido projection and all feeds have stable timestamp/id ordering.
- (decision) Vibes trim/lowercase is enforced by a database check and unique canonical value per user/book; tags render once per book. SECURITY INVOKER transaction RPC, least-privilege grants, RLS tests, private owner shelf, and restricted public Lido projection define access.
